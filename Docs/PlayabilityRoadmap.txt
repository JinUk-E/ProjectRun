경찰과 도둑: 플레이 가독성과 웹 배포 계획

이번 적용
- 경기 시작 안내에 승리 조건, 건물 내부 탈취, 감옥 정문 외부 구출을 명시.
- 플레이어별 실제 AI 관심 상태를 표시: 추격 / 마지막 목격 위치 수색 / 추격 해제.
- 네트워크에서는 서버가 판정하고 해당 플레이어에게만 상태를 전송.
- 적 위치, 이동 방향, 안개 밖 경찰의 위치는 공개하지 않음.
- 추격, 수색, 구출 대기, 동료 체포, 알람에 따른 행동 힌트 제공.
- 경찰 속도, 탐지 거리, 체포 거리와 보상 수치는 기존대로 유지.

실제 플레이 피드백이 필요한 다음 작업
1. 발견 즉시 잡히는 사례와 벽에 걸리는 구간 수집 후 조작/AI 조정.
2. 건물별 위험한 짧은 길과 안전한 우회로를 구분. 출입구 가독성 확인.
3. 탈취 중단, 알람 유인, 구출의 선택이 유효한지 확인 후 시간/보상 조정.
4. 스킬별 유용한 상황 확보. 새 스킬보다 기존 다섯 스킬의 역할과 피드백 개선.
5. 소리와 시각 신호 보강. 색상만으로 상태를 구분하지 않고 문구도 함께 제공.
6. 방 인원과 AI 채우기 설정, 배포 버전 표시 및 오류 로그 안내.

웹 게임 전환
- 우선 대상: 데스크톱 Windows/macOS 브라우저. 모바일 브라우저는 별도 성능/입력 검증.
- Unity Web Build Support 설치 필요. 현재 로컬 Editor에는 Windows/Android/iOS 모듈만 설치됨.
- 웹 대상에서 wss 및 UnityTransport.UseWebSockets 설정 반영. 실제 브라우저 연결 검증 필요.
- LAN은 직접 UDP 연결이며 웹에서는 비활성화. 웹 메뉴는 Relay 중심으로 구성 완료.
- 로컬 Transport 소스는 Relay를 사용하지 않는 WebGL 서버 실행을 차단함. Relay 호스트는 별도 실제 빌드 검증 필요.
- HTTPS 정적 호스팅, 압축 파일 헤더/MIME 설정, 로딩 용량과 브라우저 메모리 확인 필요.
- 브라우저 탭 비활성화 시 호스트 시뮬레이션/연결 영향 확인. 상시 운영이 필요하면 전용 서버 검토.
- 에디터 컴파일 성공이나 Windows 테스트 성공을 웹 지원 완료로 간주하지 않음.
- 이번 작업에서는 웹 빌드 생성, 외부 호스팅 배포 또는 서비스를 생성하지 않음.
